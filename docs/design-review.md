# 设计评审报告：AI Markdown 文档整理工具

> 评审对象：`docs/AI Markdown文档整理工具 功能设计开发文档.md`（v1，备份于 `backup/`）
> 评审结论：**产品功能规划完整度较高（编辑/AI 整理/导出/主题体系清晰），但作为可落地的跨平台开发设计存在 6 大类 18 项缺失或不足**，直接开发将导致返工。本报告逐项列出问题，增强方案见 `docs/enhanced-design.md`。

## 1. 评审总览

| 维度 | 评价 | 说明 |
|---|---|---|
| 产品定位与用户场景 | 充分 | 定位清晰，场景覆盖全面 |
| 基础编辑功能清单 | 充分 | 对标 Typora 功能清单完整 |
| AI 功能清单 | 基本充分 | 功能项完整，缺落地机制 |
| 技术架构 | **严重不足** | 无框架选型、无进程模型、无模块接口定义 |
| 平台兼容 | **不足** | 仅列 Win/macOS/Linux，与目标（iOS/Win/Linux）不符，无移动端适配 |
| 数据机制 | **严重不足** | 无数据模型、存储位置、迁移与损坏恢复设计 |
| 安全设计 | **严重不足** | API 密钥存储、隐私上云、XSS/IPC 暴露面均未涉及 |
| 错误处理 | **不足** | 仅"失败弹窗提示原因"一句话，无错误分类/重试/降级规范 |
| 性能设计 | **不足** | 只有指标（≤1s 启动等），无实现路径（增量渲染/虚拟滚动/Worker） |
| 测试与验收 | **缺失** | 无测试策略、无验收标准 |

## 2. 逐项问题清单

### P0 — 阻塞性缺失（不补无法开发）

1. **平台目标错位**：原设计 9.1 写"Windows、MacOS、Linux"，与本项目目标 **iOS + Windows + Linux** 不符。iOS 属移动端，带来完全不同的约束：文件沙盒（无任意路径读写）、WKWebView 与 CORS 限制、无物理键盘快捷键体系、Keychain 安全存储、触屏交互与低功耗要求。原设计对此全部空白。
2. **无技术选型与架构**：五大模块仅有职责一句话，未定义前端框架、Markdown 渲染引擎（WYSIWYG 核心难点）、桌面/iOS 壳层如何共享代码、进程模型（Electron 主/渲染进程 + iOS 原生桥接）。
3. **无数据模型与存储设计**：设置、AI 配置、自定义指令、最近文件、AI 历史记录的数据结构、存放路径（桌面 userData vs iOS 沙盒）、版本迁移、损坏自愈均未定义。
4. **无安全设计**：
   - API 密钥"本地加密缓存"无具体机制（Electron safeStorage / iOS Keychain）；
   - 文档内容发送云端模型的**隐私风险**未识别，无脱敏/本地模型/隐私模式设计；
   - Markdown 内嵌 HTML 的 XSS 风险（预览与导出双入口）未考虑；
   - Electron IPC 暴露面、CSP、contextIsolation 等加固项未提及。
5. **无错误处理规范**：AI 接口错误（鉴权失败/限流/超时/网络断开/上下文超限）无分类码、重试策略、取消机制、部分成功（长文分段第 N 段失败）处理与用户提示文案规范。
6. **无测试策略**：无单元/组件/E2E 测试范围、无各平台验收标准（原任务明确要求逐平台测试）。

### P1 — 影响体验与可维护性

7. **AI 长文本机制缺失**：9.2 要求"超长文本分段处理"，但无分块策略（按段落/标题切分、token 预算、段间上下文衔接）、进度反馈、失败续跑设计。
8. **性能仅有指标无路径**：10 万字流畅编辑需要**增量解析（AST 级）+ 虚拟滚动 + 解析线程隔离**，原设计未提；渲染引擎选型直接决定可行性（marked 等非 AST 方案无法做到）。
9. **冲突处理缺失**：文档被外部程序修改（或多设备同步场景）时无检测与合并策略；自动保存与外部写入可能互相覆盖。
10. **备份机制不具体**：7.1 "AI 整理前自动生成临时备份"无存放位置、命名、保留数量、清理策略。
11. **撤销体系混淆**：9.3 "所有编辑、AI 操作支持无限撤销/重做"与编辑器历史栈实现（ProseMirror history）关系未定义；AI 历史记录（4.5）与撤销栈是两套机制，需明确边界。
12. **平台快捷键差异**：Ctrl 体系仅适用 Win/Linux；iOS 无键盘场景需触屏等价操作（选区工具栏/长按菜单）。

### P2 — 完善性缺失

13. **离线能力未定义**：本地模型（Ollama）接入仅在模型清单中一笔带过，无"离线优先/隐私模式"产品语义。
14. **可观测性缺失**：无日志分级、诊断信息导出、AI 用量（token/次数）统计，排障与成本控制无依据。
15. **国际化与无障碍**：界面无多语言规划，无键盘导航/读屏/对比度等无障碍要求。
16. **导出平台差异**：PDF/Word 导出在 iOS 端能力受限（无系统打印桥接），需按平台给出能力矩阵与替代方案（分享面板）。
17. **更新机制**：桌面端无自动更新设计（electron-updater）；iOS 受 App Store 约束需说明。
18. **同步模块过度承诺**：2 中"设置与同步模块"含云端同步，但无后端、冲突解决设计，MVP 应明确移出范围（v1 已在迭代预留中，但架构表述需修正）。

## 3. 增强设计决策摘要

针对上述问题，增强设计（`docs/enhanced-design.md`）作出如下关键决策：

| # | 决策 | 解决问题 |
|---|---|---|
| 1 | 技术栈：**Vue 3 + TypeScript + Milkdown（WYSIWYG 引擎）+ Pinia** 共享核心；**Electron** 桌面壳（Win/Linux/macOS）；**Capacitor** iOS 壳 | P0-1 / P0-2 |
| 2 | 平台适配层 `PlatformAdapter`：文件/HTTP/安全存储/导出四类能力按平台注入（Electron IPC / Capacitor 原生插件 / Web 降级） | P0-1 / P0-2 |
| 3 | 数据机制：全部状态定义为 JSON Schema，桌面存 `userData`、iOS 存 App 沙盒 + iCloud 文档区 | P0-3 |
| 4 | 安全：密钥 safeStorage/Keychain 加密、AI 发送前可选脱敏、隐私模式（仅本地模型）、DOMPurify 防 XSS、Electron contextIsolation+白名单 IPC+CSP | P0-4 |
| 5 | 错误处理：统一错误分类码 + 指数退避重试 + 可取消 + 长文分段部分成功策略 | P0-5 |
| 6 | 测试：Vitest 单测（纯函数层）+ 组件测试 + 三平台验收矩阵 + 冒烟脚本 | P0-6 |
| 7 | 性能：Milkdown 增量 AST 渲染、大纲/统计 worker 化、AI 分段流式进度、大文件延迟加载 | P1-7/8 |
| 8 | 冲突：chokidar 监听外部修改，脏/净状态分流提示 | P1-9 |

其余 P1/P2 项在增强设计对应章节逐项落地。
